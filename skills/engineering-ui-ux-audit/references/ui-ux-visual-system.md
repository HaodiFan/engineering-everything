# 视觉系统：把审美观察变成可实施的页面决策

> 本文件保留视觉机制、令牌、中文排版、配色、组件与动效的说明，供理解背景。
> **逐条评判以 [rules.md](ui-ux-rules.md) 为准。** 对应：层级与密度 `UX-VIS`；字体文案 `UX-TYPE`；颜色 `UX-COLOR`；组件 `UX-FORM-08`；响应式 `UX-RESP`；动效 `UX-MOTION`。


本文件是本技能的实践扩展，不是对 Eian《100 个提升审美的设计网站大赏》的逐条转述。网站目录提供观察入口；下列方法是结合官方文档与工程经验形成的操作建议。不要把建议、示例数值或推论写成原文结论，也不要声称某种视觉风格天然提高转化率。

## 导航

- 先决定方向：1–2
- 布局、密度与字号：3–5
- 配色、素材与组件：6–8
- 多端与动效：9–10
- 精修与交付：11–12
- 数字门槛与测试方法见 [verification.md](ui-ux-verification.md)；状态、交互与流程见 [user-flows.md](ui-ux-user-flows.md)。

## 1. 先提炼机制，再谈风格

为每个参考页面写一条观察链，而不是“高级、干净、有科技感”：

> 在什么场景，什么视觉处理让哪项信息或操作更易理解；搬到当前页面后，哪些条件仍成立，哪些不成立；用什么观察验证。

例如：参考页面用大面积留白突出单一预约入口。当前页面是每天使用数十次的调度台，直接复制会让更多任务落到首屏之外。可以保留清晰主次和统一对齐，缩小组内间距，保留任务密度。

按任务选参考，不按首页截图的漂亮程度选：

- 营销页看叙事、证据与转化入口；管理台看真实数据密度、筛选、批量操作与错误恢复。
- 对话框看打开、输入、错误、完成及关闭，不只看静态默认态。
- 参考中的素材质量、品牌认知或大幅摄影可能承担主要效果。缺少这些条件时，不能只复制容器和渐变。
- 记录参考的 URL、观察到的状态、访问日期和可借鉴机制。无法访问的交互只标“未验证”，不要从截图推断行为。
- 保留用户品牌、原有信息架构、组件库与业务约束。没有充分理由，不因审美偏好重建整个设计系统。

## 2. 写一个能约束方案的视觉简报

在改页面前，用几行写清：

1. **用户与任务**：首次了解、快速查找、连续处理，还是谨慎决策？
2. **内容主次**：本页首先回答什么，用户接下来做什么，什么是辅助证据？
3. **表达方向**：例如“可信、克制、强调信息可比性”，避免只有“现代”。
4. **保留项**：品牌色、字体许可、导航结构、设计令牌、组件 API、数据字段。
5. **可调整项**：栅格、密度、信息分组、图像、局部动效。
6. **验收证据**：指定页面、状态、视口及核心操作，不只交一张好看的截图。

不要预设所有产品都要大字号、圆角卡片、渐变、玻璃效果、深色背景或“Bento”栅格。风格服务内容和使用频率。若用户要求鲜明探索，可以给出差异明显的少量方向，但先统一内容和功能，以免把信息差误当审美差。

## 3. 内容层级与页面骨架

### 3.1 信息顺序

先去掉样式检查内容顺序：页面标题 → 当前上下文 → 关键事实或任务 → 主要操作 → 支持信息。具体顺序可随任务变化，例如告警页面应先露出风险和恢复入口。

| 观察到的问题 | 优先动作 | 可观察检查 |
|---|---|---|
| 标题只有口号，看不出产品做什么 | 补充对象、能力或结果，保留品牌语气 | 不看图片也能解释本页价值 |
| 每块都像主内容 | 用字号、位置、留白和对比度分配权重 | 扫视时能区分标题、结论、说明与注释 |
| 主按钮很多且含义近似 | 按局部任务确定强调层级，合并重复入口 | 用户能解释每个入口的区别 |
| 关键价格、限制或风险在折叠区 | 移到决定发生的位置 | 操作前无需猜测代价和条件 |
| 首屏堆满所有信息 | 保留决策必需项，把细节按需求组织 | 层级更清楚且没有隐藏必要信息 |
| 页面过长却缺少定位 | 增加章节标题、目录或合适的锚点 | 跳转后能看到标题，浏览器返回可预期 |

“一个页面只能有一个主按钮”不是规则。邮件列表、编辑器等可能有多个独立任务区域。控制的是同一决策区域内的竞争，不是机械删到一个按钮。

### 3.2 用对齐表达关系

- 同一类标题、正文、字段和操作建立可复用的起始边线。对齐视觉内容，不被图片透明边或图标画布误导。
- 相关元素的组内距离应明显小于组间距离。先用邻近和留白分组，再判断是否需要边框、底色或卡片。
- 列表用于扫描同类条目；表格用于横向比较同一组属性；卡片适合信息组合各异且需独立入口的对象。不要为了“现代感”把可比较的表格拆成难比较的卡片。
- 页面容器限制长文行长，但不应把数据工作区无意义地挤窄。必要时为正文、图表和数据表设置不同宽度。
- 视觉重排不能破坏 DOM 阅读和键盘顺序。窄屏移列前先判断逻辑顺序，再决定 CSS。

### 3.3 留白与密度

密度来自任务频率、数据量、设备和错误成本，不来自统一审美口号。

- 首次使用、复杂解释：允许更多分组留白，但减少重复装饰。
- 高频列表：压缩冗余容器和重复说明，保留易点击目标、可读字号与行间分隔。
- 审批或支付：关键对象、金额、风险和确认区域应能一起比较，不让过度留白拆散上下文。
- 比较改前改后时，同时看“首屏可见任务数”和“是否仍能正确识别操作”，不要只追求更密或更空。

## 4. 建立最小够用的视觉令牌

已有项目先复用其设计令牌。发现偏差时，区分“有理由的例外”和“偶然写死值”，只收敛后者。若从零建立，以下是命名示例，不是必须安装的依赖或强制数值：

| 类别 | 语义示例 | 决策原则 |
|---|---|---|
| 间距 | `space-inline`、`space-field`、`space-group`、`space-section` | 先体现关系，再映射到有限刻度 |
| 文字 | `text-body`、`text-label`、`text-caption`、`text-heading` | 按角色命名，不按某页某像素命名 |
| 颜色 | `surface`、`text-muted`、`border-control`、`action`、`danger` | 颜色与业务含义分离，允许主题映射 |
| 尺寸 | `content-readable`、`control-height`、`sidebar-width` | 区分阅读宽度与工作区宽度 |
| 形状 | `radius-control`、`radius-panel` | 层级有关系，不必所有元素同一圆角 |
| 层级 | `layer-dropdown`、`layer-dialog`、`layer-toast` | 统一管理，避免不断增大 z-index |
| 动效 | `motion-feedback`、`motion-panel` | 以用途区分速度与减弱动态行为 |

间距可从 4、8、12、16、24、32、48、64 CSS px 等有限刻度开始，再按项目调整。4/8 点刻度是便利工具，不是质量标准；图标光学对齐、细边框等可以有理由地偏离。

改动共用令牌前检查引用范围。若只应影响当前页面，优先局部组合或限定作用域；不要为单页修正无意改变其他产品区域。

## 5. 字体与中文排版

### 5.1 字体与字号

- 优先沿用品牌字体或系统字体栈。新增字体前核对授权、中文覆盖、数字样式、字重文件和加载成本。
- 用角色建立小型字号阶梯。长段正文可从约 16–18 CSS px、行高约 1.6–1.9 试排；紧凑表格可能需要不同设置。它们是中文阅读的探索起点，不是 WCAG 要求。
- 中文标题不要直接照搬英文展示字的极紧行高、负字距或全大写规则。混排中文、拉丁字母和数字后检查视觉重量与基线。
- 界面输入字号在移动端可从至少 16 CSS px 起步，并在目标浏览器验证聚焦行为。不要用禁止用户缩放来掩盖输入框或排版问题。
- 不要用同一字重叠加过多字号层级。先让正文、标签、辅助说明、关键数字各有稳定角色。
- 用真实字体渲染后判断，不把 CSS `font-weight` 数值当作不同字体之间的等价视觉重量。

### 5.2 中文内容的边界条件

- 用真实中文、英文名称、数字、单位、日期、长 URL 和产品编码试排，不能只用短占位文案。
- 句末标点、右括号不应频繁挤到行首；中文标题可能需要手动编辑文案，但不要堆硬编码换行来适配一个截图。
- 正文行长通过实际阅读判断。英文常见的 `ch` 度量不是中文字数；对中文内容可用合适的容器宽度并实测，不能照抄“每行 70 个字符”作为统一答案。
- 价格、数量、单位和符号应保持关联。需要比较数字时考虑等宽数字；不要为此把所有中文换成等宽字体。
- 不在重要名称、金额、限制条件上静默截断。若使用省略号，提供可触达的完整信息，不能只靠鼠标悬停。
- 对长 URL、哈希、无空格词提供断行策略；避免把一般正文全部 `word-break: break-all`，破坏英文单词和可读性。
- 日期、时区、币种和单位使用明确格式。跨地区产品不能仅靠一个货币符号或模糊的“今天”。
- 允许浏览器放大和用户文字间距覆盖，避免固定高度导致文字裁切。量化要求见 [verification.md](ui-ux-verification.md)。

### 5.3 标题是内容结构，不只是尺寸

使用符合内容层级的标题元素。不要因为样式想要更大而跳标题层级，也不要把每张卡的所有文案都做标题。字段标签保持可见；placeholder 只作示例，不替代标签。

中文语气以能预测结果为先：“保存草稿”“发送邀请”“删除 3 个项目”优于泛化“确定”。如果按钮文字变长导致布局破裂，先确认动作是否足够清楚，再改善布局，不以删掉重要对象和代价解决问题。

## 6. 配色：语义、层次与状态

[Radix Colors 的色阶用途](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)提供背景、组件、边框、实色和文字等用途的划分。借鉴的是“按用途选择颜色”，不是假设任意色阶组合都满足对比度。

### 6.1 颜色职责

- 背景和表面负责空间层次；文字负责信息层级；强调色负责交互注意；状态色负责成功、警告、错误等含义。
- 同一品牌色可用于装饰和交互，但不能让非交互标题、可点击链接和错误文字完全同形同色而无法区分。
- “次要”不等于“难以阅读”。说明、单位、禁用原因、图表轴标签仍需要合适可读性。
- 危险色只用于真实危险或错误，不为了提升点击率滥用。金融涨跌色等语义有地区差异，应明确文字和符号。
- 颜色不能单独表达状态：选中项还应有勾选、位置或边框变化；错误还应有说明；图表还应有标签、图案或可读取数据。

### 6.2 明暗主题分别设计

- 深色模式不是反相。检查表面层次、阴影可见性、图像边缘、半透明叠加、输入边框、图表、浏览器原生控件。
- 色值检查使用最终合成背景，特别是渐变、图片蒙层、透明面板和 hover/selected 叠加状态。
- 每个主题检查默认、悬停、焦点、选中、错误、禁用等实际状态，不只看令牌表。
- 尊重用户和系统主题偏好；若有切换，避免初始错误主题闪烁。只在任务范围内改主题逻辑。
- 不把所有面板都包围成同样对比度的卡片。空间层级足够时可以减少边框和阴影。

### 6.3 图表颜色

先决定比较任务，再选色：序数用有序渐变，类别用可区分分类色，偏离基准用明确的双向表达。图例与图形一致；不要用彩虹暗示不存在的顺序。检查缺失、零、负数、异常值、单一类别和高密度标签，避免漂亮但误导的比例或坐标。

## 7. 图片、图标与装饰

- 每张图片说明其职责：展示产品、解释步骤、证实结果、建立情绪，或纯装饰。不能解释职责且影响加载或注意力的图片优先删除。
- 优先真实产品状态和真实业务内容。演示数据明确标识；不得伪造客户 Logo、评论、奖项、用户数或效果数据。
- 保持图标来源、描边、填充、光学尺寸与对齐一致。图标不能代替陌生操作的清晰文字。
- 图像信息重要时提供适当替代文本；纯装饰使用空替代文本，避免重复朗读附近已有说明。复杂图表另提供关键结论和数据访问方式。
- 预留图片空间或纵横比，检查裁切是否遮住人物、产品关键部位、文本或证据。手机端可能需要不同裁切，而不是简单缩小桌面图。
- 为图片加载失败、用户关闭动图、视频未播放提供可用状态。首屏关键内容不依赖视频播放才可理解。
- 不复制参考网站的受限素材、商标背书或专有页面。学习构图和呈现机制，用有权使用的素材重新实现。

## 8. 组件选择与一致性

| 组件 | 适合解决的问题 | 常见误用与检查 |
|---|---|---|
| 按钮 | 执行动作 | 导航通常用链接；禁用需解释；提交中标签仍能识别动作 |
| 链接 | 前往资源或位置 | 文案说明目的地；保留浏览器打开新标签等能力 |
| 卡片 | 聚合一个对象的信息 | 内部多个操作不要被整卡点击区域吞掉；避免嵌套交互 |
| 标签页 | 同一上下文的并列视图 | 不把所有页面导航都做 ARIA tabs；直接链接和历史行为需明确 |
| 折叠区 | 有标题可预测的次要细节 | 不隐藏决定所需的关键价格、限制、错误或必填项 |
| 表格 | 行列比较与批量处理 | 表头、排序、选择范围、空值、行操作明确；移动端不丢关键列 |
| 提示气泡 | 非必需补充解释 | 不能唯一承载错误、字段标签、关键条件或交互按钮 |
| 通知/Toast | 不中断任务的短反馈 | 重要失败要有持久恢复入口；不要只显示几秒就消失 |
| 对话框 | 有边界的任务或需立即决策的信息 | 长流程更适合独立页；键盘与焦点按标准模式验证 |

复用现有成熟组件的行为，再定制外观。视觉相似不代表语义相同：开关、复选框、单选按钮分别对应不同预期。详细选择与状态契约见 [user-flows.md](ui-ux-user-flows.md)。

## 9. 响应式：让内容决定结构变化

[Utopia](https://utopia.fyi/)提供在小屏与大屏尺度之间流式插值的思路。可用于字体、留白和容器，但不代替导航折叠、列数变化等真正的结构断点。

1. 先用最窄目标宽度容纳必要内容，再扩展到大屏。
2. 在标题撞行、导航无法容纳、表格比较失效等内容失效点设置断点，而不是只套设备名称。
3. 用有上下限的流式尺寸；不要仅用 `vw` 使文字在小屏过小或在缩放时失去可读性。
4. 避免固定高度英雄区、固定宽按钮和强制单行标题把内容推出屏幕。
5. 处理短屏、横屏、软键盘、顶部通知、底部安全区与侧栏同时出现的情况。
6. hover 增强不能是唯一入口；关键动作在触摸和键盘场景中同样可见或可发现。
7. 横向滚动限于确有必要的区域，并让滚动存在可被发现。不要让整个页面被一个超宽子元素撑开。
8. 桌面、手机和中间宽度都要截图；拖动视口经过断点，检查非预设尺寸。

列表在窄屏改成卡片前，确定字段的扫描顺序和必需信息。数据表确需保留二维结构时，可在局部滚动并保留表头关联，不能因视觉简洁直接删数据。重排不应改变读屏器和键盘对任务的理解。

## 10. 动效：解释变化，而不是拖慢任务

[Emil Kowalski 的动效示例](https://emilkowal.ski/ui/good-vs-great-animations)可用于研究触发来源、缓动和响应手感。以下为情境化的实施扩展，不是统一时长规范。

### 10.1 每段动效先回答三件事

- 用户需要理解什么变化：展开来源、对象移动、状态完成，还是纯品牌情绪？
- 用户多久会重复这个操作：每天上百次的控件应比一次性介绍更克制。
- 中途反向操作或关闭会怎样：能否从当前位置连续转向，而不是等上一段播完？

### 10.2 实施起点与例外

- 局部反馈可以从约 100–200 ms、面板过渡从约 150–300 ms 试验；这些只是起点。操作频率、移动距离、设备与用户偏好优先于固定范围。
- 弹出层的变化应与触发位置和实际出现方向一致；碰撞后改为向上弹出时，动画原点也应适配。
- 短距离位移、透明度等通常比大范围缩放和视差更克制。尽量避免频繁触发布局的动画，但用性能记录验证，不能仅凭属性名称断言无成本。
- 不滥用 `transition: all`。显式列出需要过渡的属性，防止布局、颜色、尺寸或状态意外动画。
- 不让反馈动画延迟真实响应，不用伪进度掩盖未知完成时间。防闪烁策略不得阻止已完成操作继续。
- 对频繁输入、快捷键、拖放和批量处理优先即时反馈。不能每次输入都等待出场动画。
- 减弱动态模式保留状态变化和完成反馈，移除非必需位移、视差和反复装饰。测试该模式下内容仍出现、关闭仍完成，不能依赖动画事件才解锁逻辑。
- 自动循环、闪烁和自动播放另有无障碍风险；按 [verification.md](ui-ux-verification.md) 检查，而不是以“尊重 reduced motion”替代全部要求。

## 11. 最后一轮精修，看实际渲染

完成结构与状态后再做精修，避免把主要时间花在不可见的像素微调：

- 同类边框、阴影、圆角和图标尺寸是否一致，是否有必要的例外？
- 内嵌面板的圆角与外壳关系是否自然，内容是否因裁切丢失焦点环？
- 图标与中文文本是否光学对齐，数字是否在更新时左右抖动？
- 多行卡片标题、按钮文案和错误信息是否撑破布局？
- loading/success 切换是否引起按钮或整页跳动？
- 粘性栏与浮层叠加是否遮住内容、操作或焦点？
- 空态是否仍保持页面骨架并说明下一步，而不是整页坍塌？
- 灰阶观察是否仍可理解层级？这只是辅助诊断，不替代真实色觉和对比度测试。

不要把每个页面都润色成同一个模板。允许品牌风格与任务密度不同，但同一功能的交互预期应稳定。

## 12. 输出能被实施和验证的视觉决策

每项建议至少包含：**位置 → 可观察问题 → 修改动作 → 理由/权衡 → 检查方式**。

弱建议：“增加留白，提升高级感。”

可执行建议：“筛选标签与结果列表的距离和标签组内距离相同，难以区分两组。保留标签内部紧凑间距，扩大筛选区与结果区距离，并让结果标题显示数量；在窄屏和两行筛选标签状态下确认分组清楚且没有多占整屏。”

最终交付说明哪些令牌、组件和状态有变化，哪些是待验证假设；附同条件改前改后证据。只改颜色和圆角时，不宣称已经解决任务完成率、性能或无障碍。
