# Bombadil：UI 状态探索执行步骤

本流程由 Review 或 UI Audit 在走查前触发。目的：检查本次 UI 在不同操作顺序下仍满足业务约束。先复用项目已有配置和命令；不新增全局依赖、CI 或自动化服务。

## 1. 判断适用性，必须留下结论

- 可运行 Web UI 或可点击原型，且本次涉及以下任一行为：异步加载交错、重复提交、重试恢复、角色/权限切换、多步状态流转 → **适用，继续执行**。终端 UI 使用实际版本支持的对应 driver，不能照抄 browser 命令。
- 仅截图、纯静态内容、文案修改且无相关交互 → **不适用，记录理由**，继续其他评审。
- 适用但无法运行（工具、登录、隔离数据或运行预算等前置条件不满足）→ **未完成，记录具体尝试、原因与最小补证办法**。不得静默跳过或记为通过。
- 项目已有等效属性探索时可复用，但必须列出其状态/动作生成、业务属性和本次版本结果；仅有固定路径 Playwright 用例不足以替代。相同版本与范围已有有效证据时不重复跑。

## 2. 固定受测范围与安全的动作空间

记录 commit、入口 URL、用户角色、设备/语言、数据快照和允许操作。使用隔离测试环境、合成数据和可重置账号；在每次复现前恢复同一前置状态。

只允许本次测试动作。对共享或真实环境，默认随机动作可能触发保存、删除、发送或改权限；先限定自定义动作生成器及测试账号能力。URL 同源限制不能隔离数据，也不能代替动作限制。不能保证隔离时停在未完成，继续做安全的定向检查，不能放开默认动作碰运气。

## 3. 核验工具并准备规格

1. 查项目已有依赖、脚本和 Bombadil 规格；复用项目包管理器与锁定版本。运行项目 CLI 的 `--version`、`browser test --help`，保存输出。CLI 缺失时，先检查项目允许的本地或临时安装方式，在已有授权内按官方说明补齐并重试；不能因首次 command not found 就跳过。确实无法补齐时，记录查找/安装尝试与原因，未解决前不得判通过，不把不存在的命令写成已执行。
2. 无现成规格时，从已确认验收项提炼本轮业务属性，并明确关联场景，例如：过期响应不覆盖当前选择、服务故障不显示正常空态、已验收成果不因迟到操作改变。每项写出前置状态、可观察判据和触发动作；观测不到的后端约束补 API 测试并保留 UI 证据边界。
3. 规格须包含能到达目标状态的动作和真正检查业务结果的属性。仅导出默认异常属性、只检测标题存在，不能声称验证了业务状态流转。限定动作后确认目标页面和状态仍可达；无有效动作或只停留登录页记未完成。
4. 对照实际安装版本的官方类型与文档编写规约；不要凭记忆编造时序算子或选项。使用已确认需求可直接起草，只有业务含义不清才请求澄清。原型结果仅适用于原型。

## 4. 实际运行有界探索

先选定时间预算、范围和输出目录，采用项目已有配置。无项目预算时，EE 首轮使用 **1 分钟**，这只是初始探索预算，不能证明穷尽状态。长任务使用后台运行并读取进度；不得因需要向用户汇报就把未结束的任务写成通过。

以下 browser 命令对照官方手册 v0.7.10（2026-11-19 核验）；实际运行先用本机 `--help` 核对。`bombadil` 表示项目已解析的 CLI。URL、规格与唯一输出路径替换为当前任务值，不修改项目全局配置：

```sh
bombadil --version
bombadil browser test --help
bombadil browser test --headless --time-limit 1m --exit-on-violation --output-path ./output/bombadil/review-001 http://127.0.0.1:3000 ./bombadil/review.spec.ts
```

**只有第 2 步的隔离与动作边界准备完成，才能运行最后一条。** 不带规格的默认运行只用于隔离环境中的工具 smoke，不能作为业务属性探索完成的证据。保存真实命令、标准输出/错误、退出码和工具报告；命令返回成功也要核对有没有实际动作、目标状态是否到达、属性是否参与检查、是否有违规。

## 5. 处理发现与不完整运行

- 发现属性违规：保留 trace、属性和规格、环境及数据前置条件；确认属性本身符合需求，再按业务影响定级。按工具输出的重放命令复现，保留无法重放的分歧；需要时缩减动作序列，修复后加入确定性回归。
- 规定预算正常结束、目标动作与属性确实运行、没有违规：只写“在该版本/范围/预算内未发现违规”；不要写无 bug 或所有状态正确。
- CLI/浏览器失败、外部超时、被中断、登录未完成、目标状态不可达、缺少业务属性：记未完成并说明补证。与正常按预算结束区分。
- 检查器仅核对汇总证据，不能替你判断上述条件。发现 P0/P1 可以阻断发布或提前结束本轮，但余下计划保持未完成。

复现优先采用原运行打印的命令与相同设置。browser 手册提供 `bombadil browser test --reproduce ./output/bombadil/review-001 http://127.0.0.1:3000 ./bombadil/review.spec.ts`；复现不带 `--time-limit` / `--exit-on-violation`，不要保证一定重放成功。

## 6. 交回证据与复验

报告必须出现一项 Bombadil/等效状态探索记录，最小包括：

- 适用 / 不适用及理由；实际执行为完成、发现违规或未完成。
- 受测 commit、URL、角色与隔离数据说明；工具版本和真实命令（日志中的凭证需脱敏）。
- 验收项 → 属性 → 动作/目标状态映射；规格路径、预算、实际运行结果、输出/trace 路径、退出码。
- 发现及复现结果；跳过或未完成项的具体原因、替代检查、补证动作与残余风险。

证据包可复用现有 `steps[].method`、`evidence`、`reason` 和 `unrun_checks` 字段；方法判断和运行记录放在引用的评审报告中。通用门禁目前不自动推断 UI 复杂度，汇总机检成功不能代替本流程。

修复后复验相同属性与确定性回归；换版本、账号或范围后，重新确认原证据是否有效。Review 与 UI Audit 交接同一份证据，避免重复运行。
