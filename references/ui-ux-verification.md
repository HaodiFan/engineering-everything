# 验收手册

> 本文件保留检查矩阵、可引用阈值与验收句式。逐条评判仍以 [rules.md](ui-ux-rules.md) 为准，尤其是 `UX-COLOR-02`、`UX-RESP-04`、`UX-A11Y-*`、`UX-PERF-02`、`UX-RISK-02`。

## 证据分级

静态截图或设计稿不能单独证明：焦点移动、键盘完整通路、路由与返回、真实提交与幂等、异步竞争、读屏、权限实装、减弱动态后的逻辑、真实用户性能。这些情况在规则记录里写「未验证」，不要写成通过。

实验室测量不能替代现场用户数据；脚本扫描不能替代手动键盘与辅助技术抽查。不要用一次实验室结果宣称 Core Web Vitals 已达标。

以下检查矩阵和阈值是从参考资源扩展的工程检查，不是原文规范。按页面风险选择场景，先走主要任务，再看风格。

## 状态探索的前置步骤

可运行 UI 涉及异步交错、重复提交、重试恢复、角色/权限切换或多步状态流转时，先按 [Bombadil 执行步骤](bombadil.md) 实际运行并留证。仅截图或本次无相关交互时记录不适用；无法运行时记录尝试、原因和补证办法，保持未完成。下面的定向检查不替代属性探索。

## 陌生语言检查：UI 是否 speak for itself（UX-VIS-09）

每次界面评判记录此项为通过 / 不通过 / 不适用 / 未验证。按下面顺序检查：

1. **定任务**：选本次核心任务及基础操作，写清成功条件；例如定位一个工作、展开详情、找到返回路径。只向观察者说明目标，不提示按钮名称、位置或操作路径。
2. **制作陌生版本**：在隔离预览或截图副本中，把全部可见文字替换为观察者无法解读的语言或伪文字，覆盖标题、导航、按钮、字段标签、占位符、提示、状态、tooltip、弹层及图中嵌字。保留近似字长、行数、字重、占位、分组、图标、颜色、控件形态和交互；不能用 display:none 隐藏文字或改乱布局，不能只换标题。新出现的状态也须处理。保留替换清单、遗漏和原版对照。
3. **先看陌生版本**：检查哪些是导航、哪些能点击/输入/选择、主次动作在哪里、当前选中/加载/成功/失败如何表达，以及如何退出或返回。观察者不能通过翻译、DOM 原文、无障碍名称、原文 tooltip 或已知路径解码；熟悉原界面的观察者须披露记忆影响，不能据此声称新用户验证通过。
4. **实际操作**：有可运行目标时，在隔离数据上完成所选基础任务，记录第一步、犹豫、误点、恢复及结果。只有截图时只记录“能否指出交互线索”，操作与完成能力标未验证；未制作陌生版本则本项整体未验证，不得仅靠想象原页面打勾。
5. **给结论并修复**：主导航、主操作或反馈因缺少视觉线索而无法辨认，按 UX-VIS-09 报告不通过，写清 UI 没有独立表达的部分。优先改善结构、位置、形态和状态；保留必要文字，不能靠堆解释段落或删除标签解决。相同任务与视口重做检查。

判断边界：检查基础可操作性；需要读懂正文、专业字段、合同或金额才能作出的业务决定，单独检查内容理解与风险提示。测试阶段不执行真实付款、删除或发送，也不改生产文案、实际权限、无障碍语义。陌生语言测试不替代正常语言可读性和无障碍检查。

记录模板：页面/任务 → 版本/视口 → 替换范围及原版/陌生版证据 → 观察者熟悉度 → 能辨认/不能辨认的交互 → 实际操作或仅视觉观察 → 结论与边界 → 最小修复/复验。

## 检查矩阵
| 场景 | 怎么查 | 通过条件 |
|---|---|---|
| 陌生语言 / UI 自解释 | 按上节替换可见文字后，检查导航、动作、控件与反馈 | 基础操作不依赖读懂原文；证据不足则未验证 |
| 主要任务 | 用真实内容从直接链接和常用入口各走一次 | 用户知道当前位置和下一步，结果可识别，关键输入与数据正确 |
| 异常路径 | 注入空数据、无结果、慢响应、失败、重试 | 提示区分原因，修复动作清楚，重试不丢已填数据、不重复提交 |
| 导航与状态 | 从筛选列表进入详情，返回、刷新、复制链接 | 可分享状态按设计保留，临时数据和敏感内容不泄露 |
| 响应式 | 窄手机、平板、桌面、长标题、中英混排、浏览器缩放 | 内容重排，必要操作不隐藏、不重叠。不能重排的数据区域可独立滚动 |
| 键盘与读屏 | Tab / Shift+Tab、Enter、Esc；探索模态及动态通知 | 焦点可见、不被遮挡，交互名称含义明确，焦点在关闭后回到合理位置 |
| 动效 | 常规与减少动态效果；快速重复触发、反向和打断 | 功能不依赖动画，方向与状态一致，快速交互不锁住界面 |
| 性能 | 冷启动和交互；移动或限速环境；比较基线与改后 | 关键路径不退化；记录设备与测量条件，不能以一次实验室测试替代现场数据 |
| 回归 | 回归权限、路由、表单提交、辅助状态、埋点，跑项目已有检查 | 未授权页面不改变，既有业务条件未被视觉改版破坏 |

## 要分清的阈值
- [WCAG 2.2](https://www.w3.org/TR/WCAG22/) AA：普通文字通常 4.5:1，大文字 3:1，按标准适用条件和例外判断；判断组件边界/状态所需视觉信息通常与相邻颜色有 3:1。颜色不能是传递意义的唯一方式。
- WCAG 2.2 AA 的目标尺寸是 24×24 CSS px 或符合间距等例外；44×44 CSS px 属于更高的增强目标（或平台设计建议），不是所有网站的 AA 要求。
- WCAG 重排检查通常以等效 320 CSS px 的宽度或 256 CSS px 高度（分别针对纵向和横向滚动的内容）测试；确需二维布局的内容有例外。测试 200% 文本放大，以及焦点不被粘性头尾完全遮挡。脚本扫描不能替代手动操作。
- [Core Web Vitals](https://web.dev/articles/vitals) 的“良好”目标：LCP ≤ 2.5 s、INP ≤ 200 ms、CLS ≤ 0.1，以真实用户访问的第 75 百分位判断，移动和桌面分别观察。实验室没有可代表真实用户的 INP 数据时，如实报告。
- 首次点击、完成率、耗时、错误与回退都依业务设计基线；不要承诺统一的转化提升。动效时长和触控热区应参考平台与任务，不能硬套同一数值。

## 写可验收的改动
格式：在某前置条件下，通过某操作，出现可见的结果；另附失败或返回时的处理。
- 订单列表：输入存在的订单号，应找到对应订单并能进入详情；无匹配时保留关键词，清除后恢复；从详情返回保留筛选状态，若原流程支持滚动恢复则复测。
- 注册表单：在验证请求失败时保留合理的非敏感输入，标出可修正字段并可重试；检查正常提交不会重复创建；键盘和读屏能找到错误位置。
- 营销页：窄屏保留一句价值主张和一个明显主行动；长翻译不推动 CTA 溢出；关闭动画时仍显示同样信息和操作。

## 汇报模板
- 范围和限制：页面、环境、角色、数据、是否允许改代码。
- 发现：优先级、证据、任务影响、信心。
- 变更：组件和文件、为何是最小方案、有意保留什么。
- 验收：已运行场景、实测结果、失败与遗留项、无法验证的设备或状态。
- 建议：若需行为结论，建议小样本可用性任务或对照指标，明确后续样本和成功条件。
