# UI/UX 评判规则

逐条规则用于判断界面**哪里不好**。每条含：可观察触发条件、适用与反例边界、证据要求、严重度、修复建议、复验。结论只许：通过 / 不通过 / 不适用 / 未验证。

区分标准门槛和经验默认：声明符合 WCAG 等标准时，必须按对应版本、适用条件和例外核验，不得任意降低门槛后仍声称符合；经验参数可调整并记录理由，不要把示例写成普适铁律。强制项主要涉及安全、可访问、语义真实与审计诚实。机制背景见 [visual-system.md](ui-ux-visual-system.md) 与 [user-flows.md](ui-ux-user-flows.md)；测量门槛见 [verification.md](ui-ux-verification.md)。

## 1. 审计纪律

### UX-META-01 范围或主任务未定义就下结论
- **触发：** 未说明审查哪一页、哪条任务、哪种材料，却给出「整体不好/已经很好」的判断。
- **适用/边界：** 每次评判都适用。允许在材料不足时列出假设，但不能把假设写成已证实的用户需求。
- **证据：** 记录范围、主任务（用动词）、材料类型和假设。
- **严重度：** 流程错误，先补范围再评；若已对外给出无范围的定性结论，视为严重。
- **修复建议：** 补写任务与范围后再评判。
- **复验：** 每条发现都能指回范围内的位置和任务。

### UX-META-02 把未观察到的行为写成已验证
- **触发：** 静态截图或未实测的能力，被写成「焦点正确」「返回会保留筛选」「性能合格」「读屏可用」「主路径已跑通」。
- **适用/边界：** 凡涉及焦点、路由、提交、异步、权限实装、性能、辅助技术、减弱动态后的逻辑，截图默认不足。能打开原型或产品则应实际操作后再下结论。
- **证据：** 写清操作步骤或明确标注未验证原因。
- **严重度：** 把未验证写成通过，视为严重（审计诚实，强制）。
- **修复建议：** 改为未验证，或补做可复现检查。
- **复验：** 结论与证据类型一致，未测项不会出现在「通过」里。

### UX-META-03 编造综合分或未经证实的效果
- **触发：** 出现总分、审美分，或承诺「这样会提升转化/完成率」，但没有对应实验或数据。
- **适用/边界：** 有真实基线数据时可引用该数据，不可发明分数或统一转化保证。
- **证据：** 任何效果声明都要有来源与条件。
- **严重度：** 强制。误导决策时为严重或阻断。
- **修复建议：** 删除分数与效果承诺，改回按规则与证据的发现列表。
- **复验：** 交付中无综合分，无无来源的效果断言。

### UX-META-04 用偏好或参考站风格代替当前任务证据
- **触发：** 以「不够高级」「不像某获奖站」为由要求改版，而未说明对当前任务的妨碍。
- **适用/边界：** 参考站可提供机制假设，不能证明当前任务失败。生产规范、品牌与设计系统优先于灵感库。
- **证据：** 说明可观察的任务或可读性问题；参考需写适用条件。
- **严重度：** 一般；若因此建议推翻现有系统或忽略风险信息，升为严重。
- **修复建议：** 改写为可观察问题，或标为建议并注明是风格偏好。
- **复验：** 每条不通过都能指出对理解、操作或风险的影响，或被明确标成建议。

### UX-META-05 超出授权实施
- **触发：** 用户只要求评判，却改代码、发消息或提交；或改动超出授权页面与共用组件。
- **适用/边界：** 实施须有明确授权。概念稿不能当作已覆盖生产实现。
- **证据：** 对照用户请求与实际动作。
- **严重度：** 强制。可能造成阻断级生产风险。
- **修复建议：** 停止实施，先交付评判；实施须另确认范围。
- **复验：** 未授权时交付仅含评判与建议。

## 2. 任务与流程

### UX-FLOW-01 没有可检查的成功条件
- **触发：** 只能描述「点了按钮」，不能说明系统怎样才算完成，或界面成功不等于真实完成。
- **适用/边界：** 有后端或真实结果的流程适用。纯展示页若不涉及提交，可不适用。无法接通后端时，须标注未接通部分，不能把原型动画当完成证据。
- **证据：** 任务卡中的成功证据；交互或接口验证。仅截图通常未验证。
- **严重度：** 主任务完成条件含糊为严重；已把界面成功当成不可逆完成（支付、发送）为阻断。
- **修复建议：** 分开「已点击」与「已保存/已接受」，成功态展示对象与后续状态。
- **复验：** 能指出代表完成的系统结果，失败与离开后知道如何继续。

### UX-FLOW-02 用错页面类型的检查重点
- **触发：** 用营销首屏手法要求工具台大留白全屏动效，或把资料库页面当成转化落地页来评。
- **适用/边界：** 先按页面类型看首要任务。类型矩阵见 user-flows.md。不要求每页具备所有模块。
- **证据：** 页面类型、高频任务与被批评项是否匹配。
- **严重度：** 一般；若建议会降低任务效率或隐藏风险，升为严重。
- **修复建议：** 改用与该类型匹配的规则和参考，不整套搬外观。
- **复验：** 建议直接服务该页首要任务。

### UX-FLOW-03 为减少步骤去掉必要审阅或确认
- **触发：** 以「少一次点击」为由，去掉费用核对、明确同意或高风险确认。
- **适用/边界：** 低风险且可撤销的操作可以简化确认。法律、支付、权限、不可恢复变更除外。
- **证据：** 被删除步骤是否承载代价或同意；是否另有审阅机会。
- **严重度：** 高风险场景为阻断或严重；低风险过度确认为建议。
- **修复建议：** 保留必要审阅，把确认集中在真正有代价的一步。
- **复验：** 代价信息在提交前可见；低风险操作不再被无必要对话框打断。

## 3. 导航与位置

### UX-IA-01 无法识别当前位置与下一步
- **触发：** 看不出自己在哪、当前对象是什么、下一步做什么。
- **适用/边界：** 多层级、多对象、多步骤流程尤其适用。单屏营销页可只检查行动目标是否清楚。
- **证据：** 标题、选中导航、面包屑或步骤指示是否反映语境。
- **严重度：** 主任务因此迷路为严重；次要页不清晰为一般。
- **修复建议：** 用标题和导航状态显示当前对象与任务，而不是只靠视觉装饰分区。
- **复验：** 不依靠记忆也能说出当前位置和下一步。

### UX-IA-02 应可恢复的视图状态在返回或刷新后丢失
- **触发：** 筛选、排序、分页、展开等可分享或应可恢复的状态，在刷新、复制链接或浏览器前进/后退后丢失；或把敏感信息写入 URL。
- **适用/边界：** 适用于设计为可恢复的状态。临时焦点不必进 URL。敏感数据不得因可分享而泄露。仅截图无法证明，标未验证。
- **证据：** 实际返回、刷新、复制链接的结果。
- **严重度：** 比较或查找任务因此返工为严重；敏感信息泄露为阻断。
- **修复建议：** 可分享状态按设计写入 URL 或等价恢复机制，并排除敏感字段。
- **复验：** 从已筛选列表操作后返回或刷新，状态符合设计且无泄露。

### UX-IA-03 从列表进入详情再返回后找不到原对象
- **触发：** 返回后筛选、页码、选择或滚动位置被重置，用户须重找对象。
- **适用/边界：** 深列表、搜索结果、批量处理尤其适用。若产品明确重新加载且有说明，评估是否可接受。截图不能证明，标未验证。
- **证据：** 记录进入前位置与返回后位置。
- **严重度：** 高频查找场景为严重，否则为一般。
- **修复建议：** 返回时恢复合理的列表上下文。
- **复验：** 在筛选后的靠后位置进入详情再返回，仍能认出同一对象。

### UX-IA-04 链接与按钮语义用错
- **触发：** 页面跳转做成无法新标签打开的假按钮；提交或危险动作做成看起来像普通链接且无预警。
- **适用/边界：** Web 适用。原生元素优先。允许样式相似，但行为须符合控件类型。
- **证据：** 交互：右键/中键、复制地址、Enter 提交。截图只能标疑点，结论常为未验证。
- **严重度：** 破坏导航习惯或导致误提交为严重。
- **修复建议：** 导航用链接，动作用按钮，并保留平台惯用行为。
- **复验：** 跳转可按平台方式打开；动作不会被当成单纯导航。

### UX-IA-05 离开拦截不当
- **触发：** 有未保存且会丢失的输入却不提醒；或没有修改也被反复拦截。
- **适用/边界：** 仅在确有丢失风险时提醒。截图不能证明，标未验证。
- **证据：** 改与不改两种离开路径。
- **严重度：** 可能丢草稿为严重；无修改也拦截为一般。
- **修复建议：** 按是否脏检查决定是否提示。
- **复验：** 有修改离开会提醒，无修改可直接离开。

## 4. 视觉层级与布局

### UX-VIS-01 不看图无法理解本页价值或任务
- **触发：** 标题只有口号，去掉图片或装饰后说不出本页做什么、给谁、下一步是什么。
- **适用/边界：** 营销和首次到达页尤其适用。已登录工具页看当前任务与对象是否清楚，不要求再写广告语。
- **证据：** 仅读文字与标题做复述。
- **严重度：** 首次无法判断是否相关为严重，否则一般。
- **修复建议：** 在标题或首屏文案中补对象、能力或结果，保留品牌语气。
- **复验：** 不看图片也能解释本页价值和主行动。

### UX-VIS-02 扫视无法区分主次
- **触发：** 每个区块的字号、对比和位置都像主内容。
- **适用/边界：** 适用于内容层级。不是要求减少功能，而是分配权重。
- **证据：** 灰阶或快速扫视能否分出标题、结论、说明与注释。
- **严重度：** 主任务信息被淹没为严重，否则一般。
- **修复建议：** 用位置、字号、留白和对比分配权重。
- **复验：** 数秒扫视能指出本页最重要的信息和行动。

### UX-VIS-03 同一决策区内行动互相竞争
- **触发：** 同一决策步骤里多个行动视觉权重接近、含义相近，无法判断当前该点哪个。
- **适用/边界：** 控制同一决策区内的竞争。页面可有多个独立任务区，各有主操作；**不是**「整页只能有一个主按钮」。
- **证据：** 标注这些行动的视觉权重与任务关系。是否真的点错需观察，否则影响标未验证。
- **严重度：** 主任务卡住为严重；次要区重复为一般或建议。
- **修复建议：** 拉开层级或合并重复入口，写清区别。
- **复验：** 能说明每个入口的差别，当前任务下一步清楚。

### UX-VIS-04 决策所需代价或限制远离操作点
- **触发：** 价格、费用、库存、权限、不可逆后果等放在折叠区、另页或远离行动按钮的位置。
- **适用/边界：** 只要求做决定时必须知道的信息出现在决策点。细节仍可展开。
- **证据：** 操作前能否看到对象、代价与条件，无需猜测。
- **严重度：** 涉及付费、法律或不可逆变更为严重或阻断，否则一般。
- **修复建议：** 把代价和限制移到行动附近，折叠只放真正次要的细节。
- **复验：** 操作前不必翻找即可说出代价和条件。

### UX-VIS-05 分组与对齐不能表达关系
- **触发：** 相关标签、数值和操作对不上；或组内间距与组间间距几乎相同。
- **适用/边界：** 先用邻近和留白分组，不是每组都必须做成卡片。对齐看视觉内容，不被图标画布或透明边误导。
- **证据：** 标注应对齐的边线和组内/组间距离。
- **严重度：** 一般；导致填错字段或看错对象时为严重。
- **修复建议：** 统一同类起点边线，让组内明显近于组间。
- **复验：** 能正确对应字段、数据与动作。

### UX-VIS-06 比较型数据用不适合比较的容器
- **触发：** 需要横向比较同一组属性的数据被拆成难以对齐的大卡片；或本应独立进入的异质对象被硬塞进不适合的表。
- **适用/边界：** 列表扫描同类项，表格比较属性，卡片承载信息组合各异且需独立入口的对象。不要为「现代感」牺牲可比较性。
- **证据：** 指出无法并排比较的字段，或表格对异质对象的牵强之处。
- **严重度：** 核心工作是比较时为严重，否则一般。
- **修复建议：** 改回可比较的表格或提供比较视图；异质对象再用卡片。
- **复验：** 目标属性可在同一视范围内比较，关键列在适用视口仍可及。

### UX-VIS-07 密度与任务频率或错误成本不匹配
- **触发：** 高频工作台被过大留白和重复容器拉开，或高风险核对区被拆散；相反，复杂首次说明被压成难读的密块。
- **适用/边界：** 密度来自频率、数据量、设备和错误成本，不来自统一审美口号。不要只追求更密或更空。
- **证据：** 首屏可见任务数与是否仍能正确识别操作，一并比较。
- **严重度：** 一般；若导致误操作或主任务落到首屏之外且无导航补偿，升为严重。
- **修复建议：** 高频区压缩冗余容器，审批/支付区让对象与代价可一起看。
- **复验：** 目标任务可高效到达，关键上下文仍能一起核对。

### UX-VIS-08 视觉顺序与阅读或键盘顺序冲突
- **触发：** 视觉上先看到的操作，在 DOM 或 Tab 顺序中很晚才出现，或窄屏重排后逻辑乱序。
- **适用/边界：** 视觉改排不能破坏阅读和键盘顺序。仅截图不能证明键盘顺序，标未验证。
- **证据：** 对比视觉顺序与 Tab/读屏顺序。
- **严重度：** 核心任务顺序错误为严重。
- **修复建议：** 先定逻辑顺序，再写布局和 CSS。
- **复验：** 键盘与视觉的任务顺序一致。

## 5. 排版与文案

### UX-TYPE-01 正文难以持续阅读
- **触发：** 正文字号过小、行距过紧或过松、行长过宽或过窄，阅读吃力。
- **适用/边界：** 长文、说明、设置解释适用。紧凑表格和控件标签可另设，不套用同一行长。英文常见每行 45–90 字符、行距约 120–145% 只是拉丁正文参考（Practical Typography），**不是中文字数铁律**，也不是 WCAG 字号要求。中文用容器宽度和实测判断。
- **证据：** 真实语言的长文样例，而不是短占位词。
- **严重度：** 一般；主内容几乎无法阅读为严重。
- **修复建议：** 先调正文角色，再调展示标题。为正文和工作区设置不同宽度。
- **复验：** 目标语言下可连续阅读，不靠截图硬换行维持效果。

### UX-TYPE-02 中文或混排套用不当的拉丁展示规则
- **触发：** 中文标题照搬极紧行高、大额负字距或全大写规则；中西数字混排基线或字重明显失调。
- **适用/边界：** 中文、日文等不适用英文展示字的全部规则。全大写加字距是拉丁规则。
- **证据：** 真实混排样例的渲染，不是设计工具里的假字。
- **严重度：** 一般。
- **修复建议：** 按目标语言重排标题与正文，检查标点避头尾，但不要为单张截图堆硬编码换行。
- **复验：** 真实中文和混排样例在目标宽度下可读、不互相碰撞。

### UX-TYPE-03 重要文本被静默截断或破坏性断行
- **触发：** 名称、金额、限制、状态在界面上被裁切且无法触及全文；或对普通正文使用破坏英文单词的断行。
- **适用/边界：** 次要装饰性文字可省略，但须能到达全文，且不能只靠鼠标悬停。
- **证据：** 用超长真实名称、编码、URL、多币种金额试排。
- **严重度：** 关键对象或金额被截断为严重，否则一般。
- **修复建议：** 提供可触达的完整信息；为长编码设断行策略，避免正文一律 `break-all`。
- **复验：** 重要信息可完整获得；放大或长翻译不裁切关键内容。

### UX-TYPE-04 标题层级与内容结构不符
- **触发：** 因样式跳过标题层级，或把卡片里所有句子都做成标题；字段只用占位符当标签。
- **适用/边界：** 标题反映内容结构。占位符只作示例，不替代可见标签。
- **证据：** 标题大纲与可见标签。读屏顺序若未测则该项未验证。
- **严重度：** 一般；表单因此无法理解为严重。
- **修复建议：** 按结构使用标题元素；标签保持可见。
- **复验：** 大纲可理解，字段在聚焦前就能看到标签。

### UX-TYPE-05 操作文案不能预测结果
- **触发：** 主按钮是泛化的「确定」「提交」「好的」，看不出对象和后果。
- **适用/边界：** 低风险次要对话框可用短文案。破坏性或批量操作应说出对象和动作。文案变长时先保证含义，再改布局，不靠删掉对象和代价来塞按钮。
- **证据：** 只看按钮能否预判结果。
- **严重度：** 高风险操作为严重，否则一般。
- **修复建议：** 改成「保存草稿」「发送邀请」「删除 3 个项目」这类可预判文案。
- **复验：** 不看正文也能大致说出按下后会发生什么。

### UX-TYPE-06 错误或状态文案不可行动
- **触发：** 只有「参数错误」「失败」；或把系统失败归咎于用户，且无下一步。
- **适用/边界：** 能确定原因时说明对象、问题与修复；不能确定时坦诚，并给重试或支持路径。避免羞辱性微文案。
- **证据：** 错误文案全文与旁边的行动。
- **严重度：** 用户无法从失败恢复为严重，否则一般。
- **修复建议：** 写成可执行说明，例如「结束日期须晚于开始日期，请调整其中一个日期」。
- **复验：** 看到错误后知道改什么、去哪里改。

## 6. 颜色与对比

### UX-COLOR-01 仅用颜色传递意义
- **触发：** 状态、选中、对错或图例只靠颜色区分，去掉颜色后无法理解。
- **适用/边界：** 强制。颜色可作编码之一，必须另有文字、图标、形状、位置或图案。
- **证据：** 灰阶或模拟色盲后是否仍可理解。真实色觉用户测试未做则不声称已完成用户验证。
- **严重度：** 关键状态不可分为严重或阻断。
- **修复建议：** 补文字、符号或形状编码。
- **复验：** 不依赖色相也能区分状态。

### UX-COLOR-02 对比不足
- **触发：** 正文、标签、禁用原因、轴标签或按钮文字与最终合成背景对比不足。
- **适用/边界：** 强制可访问项。若项目采用 WCAG 2.2 AA，普通文字通常 4.5:1，大文字 3:1，判断组件边界/状态所需信息通常与相邻色 3:1，按标准例外判断。APCA 可作补充分析，但不能替代所声明的 WCAG 2.x 对比度符合性判断。须在最终背景（含渐变、图片、叠层、透明面板）上测量。「次要」不等于可以难以阅读。无法测量则未验证。
- **证据：** 对比测量值、前景背景色、所采用标准。
- **严重度：** 主内容或关键控件不合格为严重，次要说明为一般。
- **修复建议：** 提高对比，而不是只把文字标成 muted 了事。
- **复验：** 按声明标准复测通过，含悬停、选中和错误态。

### UX-COLOR-03 语义色与真实含义不符
- **触发：** 危险色用于普通强调或促销；涨跌色无文字说明且忽略地区差异；错误、警告、成功混用。
- **适用/边界：** 危险色用于真实危险或错误。金融颜色有文化差异，需文字或符号。
- **证据：** 颜色角色与文案是否一致。
- **严重度：** 导致危险操作被看成为安全或常规为严重，否则一般。
- **修复建议：** 把语义色绑定含义，并补非颜色编码。
- **复验：** 同类含义用同类编码，且不靠颜色单独成立。

### UX-COLOR-04 深色或多主题未按最终状态检查
- **触发：** 深色模式只是反相；或仅看令牌表，未检查输入边框、叠层、图表、原生控件和悬停/焦点/错误态。
- **适用/边界：** 有多主题时适用。深色不是反相。尊重系统偏好，避免首屏闪错主题。
- **证据：** 各主题下默认与交互状态的实际渲染。
- **严重度：** 一般；关键文本或错误态不可读为严重。
- **修复建议：** 按主题重做表面层次与对比，在合成背景上复测。
- **复验：** 每个主题下状态可分辨、文字可读。

### UX-COLOR-05 图表配色误导比较
- **触发：** 用彩虹暗示不存在的顺序，图例与图形不一致，或漂亮的比例/坐标歪曲数据。
- **适用/边界：** 先明确比较任务再选色。检查缺失、零、负数、异常值和单一类别。
- **证据：** 指出可能被误读的编码，并对照数据。
- **严重度：** 误导决策为严重，否则一般。
- **修复建议：** 序数用有序尺度，类别用可区分色，并提供标签或数据访问。
- **复验：** 不看装饰也能正确读出比较结论。

## 7. 表单、表格与组件

### UX-FORM-01 标签不可见或以占位符代替
- **触发：** 字段没有始终可见的标签，或提交前才告知格式、字数和限制。
- **适用/边界：** 强制。占位符只作示例。标签须与控件程序化关联。
- **证据：** 空态与填写中标签是否仍在；读屏关联未测则该项未验证。
- **严重度：** 严重。
- **修复建议：** 可见标签 + 输入前可看见的格式说明。
- **复验：** 聚焦前后都能识别字段，限制不必等失败才出现。

### UX-FORM-02 禁止粘贴或阻碍密码管理器与自动填充
- **触发：** 禁止粘贴；一次性验证码只能单格手输且不能整串粘贴；阻碍自动填充或密码管理器。
- **适用/边界：** 强制。可访问认证的重要路径之一是允许粘贴和辅助填充（见 WCAG 2.2 可访问认证说明）。视觉分格可以，但必须支持整串粘贴。
- **证据：** 实际粘贴、自动填充和退格行为。截图未验证。
- **严重度：** 阻断或严重。
- **修复建议：** 允许粘贴和自动填充；验证码分格不得破坏整串输入。
- **复验：** 粘贴与管理器填充可完成，过期和错误状态可区分。

### UX-FORM-03 校验时机或错误更新不当
- **触发：** 尚未输入就满页报错；输入过程中反复打断；用户改对后仍要再提交一次才消失错误；多字段失败只有顶部一句「参数错误」。
- **适用/边界：** 默认可在失焦或提交时指出错误，并在纠正后及时更新。若采用预禁用提交，必须同时给出可见的未完成原因。**不是**「任何表单都不能禁用提交按钮」。
- **证据：** 输入前、输入中、纠正后、提交后的错误表现。
- **严重度：** 用户无法定位错误为严重，否则一般。
- **修复建议：** 保留输入，就地显示全部错误并提供跳转，纠正后及时清除。
- **复验：** 能找到每个错误并改完立即看到更新。

### UX-FORM-04 默认值代替用户作出有代价选择
- **触发：** 预选订阅、附加收费、更宽权限或隐私共享，且不易发现和更改。
- **适用/边界：** 符合上下文、易改的默认可以使用。涉及费用、隐私或权限时不得冒充用户选择。
- **证据：** 默认值、展示位置和更改成本。
- **严重度：** 涉及费用、隐私或权限为严重或阻断，否则一般。
- **修复建议：** 改为明确选择，或把默认展示得可发现且易改。
- **复验：** 有代价选项不会在用户未察觉时被选中。

### UX-FORM-05 控件预期与生效时机不符
- **触发：** 开关样式暗示即时生效，实际要等「保存」；或相反，已保存却无反馈。
- **适用/边界：** 开关通常表达即时状态；若统一保存，必须明确说明。截图只能标疑点。
- **证据：** 拨动后刷新或离开再回来，看是否真正生效。
- **严重度：** 权限或安全设置因此误判为严重，否则一般。
- **修复建议：** 改控件或补「未保存/已生效」说明。
- **复验：** 用户能判断现在改的是本地草稿还是已生效配置。

### UX-FORM-06 提交保护不足或把未知结果当失败重试
- **触发：** 提交中仍可重复发出有副作用请求；或结果未知时显示失败并鼓励再次支付、发送或创建。
- **适用/边界：** 前端禁用不能当成完整幂等保证。支付、外发、建单在结果未知时应查询状态，而不是直接再提交。仅截图未验证。
- **证据：** 快速连点、弱网或超时后的界面与实际对象数量。
- **严重度：** 可能重复扣款、发送或创建为阻断。
- **修复建议：** 提交中防重复，未知结果提供查单/恢复路径，服务端做幂等。
- **复验：** 连点或超时不会造成重复副作用，按钮在提交中仍能识别原动作。

### UX-FORM-07 筛选、搜索、空态或选择范围不明确
- **触发：** 无结果时清掉查询且无法恢复；空数据与请求失败同一句话；批量操作未说明是当前页还是全部筛选结果。
- **适用/边界：** 搜索、目录、数据表适用。选择范围必须可理解。
- **证据：** 无结果、失败、多选后的文案与实际作用范围。返回恢复见 UX-IA-02，勿重复计分，可交叉引用。
- **严重度：** 批量作用范围不清为严重；空态含混为一般或严重（视是否丢失查询）。
- **修复建议：** 保留查询与可清除的筛选；区分空与失败；写清选择范围。
- **复验：** 用户能解释当前结果为何出现、批量会作用于哪些对象。

### UX-FORM-08 组件模式误用
- **触发：** 整张卡片的点击区域吞掉内部按钮；用 Toast 几秒后消失作为唯一的失败恢复入口；关键条件只放在悬停提示里；复杂表单塞进菜单；把整站导航做成不支持直达链接的 Tabs。
- **适用/边界：** 按职责选组件。提示气泡不承载错误、标签或必操作；重要失败要有持久入口。细则见 visual-system.md 组件表与 APG 模式。
- **证据：** 指出冲突的交互或转瞬即逝的关键信息。
- **严重度：** 关键失败无法找回，或内部操作点不到，为严重，否则一般。
- **修复建议：** 拆开嵌套点击，把关键失败放到页面内可再次到达的位置。
- **复验：** 内部操作可独立使用；失败后仍能看到恢复入口。

## 8. 状态与数据真实性

### UX-STATE-01 界面状态与系统事实不一致
- **触发：** 把未知、排队、部分完成或失败显示为成功；或把缺失值显示为真实的零。
- **适用/边界：** 强制。页面状态不能代替事实状态。「能连通」不是「服务可用」。不可逆操作不得仅凭乐观动画宣告成功。
- **证据：** 对照界面文案/颜色与真实或可查的系统状态。无法核对则未验证，不得写成通过。
- **严重度：** 阻断。
- **修复建议：** 分开成功、失败、未知、进行中，成功只在事实成立后出现。
- **复验：** 每种非成功状态都不会被看成已完成。

### UX-STATE-02 空、无结果、失败、权限混用同一表达
- **触发：** 「暂无数据」同时用于尚未创建、筛选无命中、接口失败和无权查看。
- **适用/边界：** 不同原因要有不同说明和出口。权限提示不得暴露无权知道的对象或内部规则。
- **证据：** 分别构造或指出这些状态的文案与行动。
- **严重度：** 严重；若掩盖失败或泄露权限信息，升为阻断。
- **修复建议：** 为各状态写原因和下一步（创建、改筛选、重试、请求权限或返回）。
- **复验：** 能区分这些状态，且出口与原因匹配。

### UX-STATE-03 加载反馈不当
- **触发：** 瞬时操作也闪骨架；不可测进度被编成线性百分比；局部请求却用全页遮罩；重试无限旋转没有出口。
- **适用/边界：** 先让控件及时响应，再按延迟决定是否显示加载。骨架近似布局即可。进度可测才给百分比。截图很难证明闪烁，常为未验证。
- **证据：** 快慢两种响应、局部刷新和失败重试的行为。
- **严重度：** 一般；若阻止操作已完成的结果或让人无法退出，升为严重。
- **修复建议：** 防闪烁但不得挡住已完成状态；长任务可取消并给停止条件。
- **复验：** 快响应不闪、慢响应有说明、失败有出口。

### UX-STATE-04 过期或错误请求的数据被当成当前结果
- **触发：** 快速改筛选后旧请求结果覆盖新条件；或过期价格、过期列表不加说明仍当当前数据。
- **适用/边界：** 用请求身份或取消保证一致性。局部更新须标明仍在更新的部分。仅截图未验证。
- **证据：** 快速切换条件或等待过期数据时的界面。
- **严重度：** 可能按过期数据决策时为严重或阻断。
- **修复建议：** 丢弃过期响应，过期数据明确过期。
- **复验：** 最终展示与当前条件一致，过期信息不会被当成最新。

### UX-STATE-05 数据完整性、新鲜度或演示性质未标明
- **触发：** 部分加载却看不出哪些还在获取；演示、示例或伪造的客户评价/奖项/数量未标识，甚至伪装成真数据。
- **适用/边界：** 强制不得伪造客户、评论、奖项或效果数据。部分可用必须可见。演示数据须标明。
- **证据：** 数据来源、时间范围、缺失段和标识。
- **严重度：** 伪造社会证明为严重或阻断；新鲜度不清为一般或严重（视决策风险）。
- **修复建议：** 标明范围与时间，示例明确为示例，删除伪造背书。
- **复验：** 用户能判断哪些是真数据、是否完整、是否过期。

### UX-STATE-06 把生成过程或推测显示为完成事实
- **触发：** AI 或长任务在输出流动中就显示「已完成」；无证据的推测带有确定权威样式；「取消」掩盖已发生的外部动作；「再试一次」暗中再次发送或支付。
- **适用/边界：** 适用于生成、排队、长任务。停止按钮须说明停止的是什么。没有证据时标不确定。
- **证据：** 各阶段文案、停止/重试的实际副作用。截图通常不足。
- **严重度：** 把推测当事实或重复外部动作为阻断或严重。
- **修复建议：** 区分排队、执行、部分完成、失败和完成；引用指向支持材料；重试与再次执行外部动作分开。
- **复验：** 过程与完成可区分，取消和重试不会偷偷产生额外副作用。

## 9. 风险、权限与恢复

### UX-RISK-01 高风险提交前关键事实不清
- **触发：** 支付、法律承诺、权限变更或不可恢复提交前，看不清对象、金额与币种、费用、时间/时区、接收方、范围或重要限制。
- **适用/边界：** 强制适用于高风险页。变更对象或金额后须重新呈现，不能沿用旧确认外观。设计优化本身不授权真实交易；测试用沙箱或合成数据。
- **证据：** 提交前屏幕上的事实清单。
- **严重度：** 阻断或严重。
- **修复建议：** 提交前汇总关键事实，变化后刷新确认内容。
- **复验：** 提交前能复述对象、代价和范围。

### UX-RISK-02 不可恢复操作缺少与风险相称的保障
- **触发：** 删除、付款、外发等高代价动作可被默认焦点或误触直接执行，且无确认、审阅或撤销。
- **适用/边界：** 强制评估风险是否相称。可可靠撤销的低风险操作不必层层确认。WCAG 2.2 SC 3.3.4 要求对特定数据变更提供撤回、检查或提交前审阅等至少一种保障，不等于所有动作都要弹窗。截图不能证明撤销是否真的有效，标未验证。
- **证据：** 误触路径与恢复能力是否真实存在。
- **严重度：** 高代价且无保障为阻断或严重；低风险过度确认为建议。
- **修复建议：** 用明确动作文案 + 相称的确认或真撤销；不要在文案里发明系统没有的撤销。
- **复验：** 高风险动作需明确执行，且保障按设计生效。

### UX-RISK-03 退出或拒绝路径被隐藏或被羞辱性文案阻碍
- **触发：** 取消、拒绝、退出、导出或关闭明显更难找到；或用羞辱性文案逼迫接受。
- **适用/边界：** 接受和拒绝都应可理解、可执行。退出不应无理由地比进入更难。
- **证据：** 进入与退出路径的可见性和文案。
- **严重度：** 严重；若造成非自愿承诺，升为阻断。
- **修复建议：** 对等展示拒绝/退出，删除羞辱性微文案。
- **复验：** 不接受的路径可被发现并完成。

### UX-RISK-04 文案承诺系统并不存在的恢复能力
- **触发：** 界面写「可随时撤销/已保存到云端/已同步」，但系统没有这些能力。
- **适用/边界：** 只有真实实现才可承诺。不能让关闭浏览器后的文案保证并不存在的恢复。
- **证据：** 对照文案与实际实现。无法核对则未验证，不得写成通过。
- **严重度：** 严重或阻断。
- **修复建议：** 改文案以匹配真实能力，或先实现再承诺。
- **复验：** 按文案操作时，恢复行为确实发生。

### UX-RISK-05 权限表达不当或把隐藏控件当作安全边界
- **触发：** 用隐藏按钮代替授权；禁用没有解释；看似局部的开关实际改组织级设置；普通用户路径未验证却按管理员成功路径放行。
- **适用/边界：** 隐藏适合用户不应知道的功能；需理解条件时禁用并解释。界面提示不是安全边界，服务端授权不可少。不得暴露无权查看的数据或对象存在性。
- **证据：** 至少两种角色的可见性、解释和真实请求结果。只看管理员截图则其他角色未验证。
- **严重度：** 安全绕过或数据泄露为阻断；表达不清为严重或一般。
- **修复建议：** 按角色验证；说明作用范围；安全策略由服务端执行。
- **复验：** 无权操作失败且不泄露额外信息；有权用户能理解限制与申请路径。

## 10. 动效、性能与响应式

### UX-MOTION-01 功能依赖动画或动画不可打断
- **触发：** 必须等动画播放完才能继续；中途关闭或反向仍要播完上一段；碰撞换向后动画原点仍指向旧方向。
- **适用/边界：** 动效应解释状态或空间变化，并可以从当前进度转向。仅截图未验证。
- **证据：** 快速打开/关闭、反向、Escape 或连续触发。
- **严重度：** 锁住操作为严重，否则一般。
- **修复建议：** 让动画可打断，逻辑完成不依赖动画结束事件。
- **复验：** 快速重复和反向时界面不锁定，状态与方向一致。

### UX-MOTION-02 未提供减弱动态下的等价反馈
- **触发：** `prefers-reduced-motion` 下内容不出现、关闭不完成，或只去掉动画却丢失状态变化反馈。
- **适用/边界：** 强制。减弱模式保留完成与状态反馈，移除非必需位移、视差和循环装饰。自动播放与闪烁另见 verification.md，不能只靠这一条代替全部要求。
- **证据：** 打开减弱动态后走主路径。未测则未验证。
- **严重度：** 功能在该模式下不可用为阻断或严重。
- **修复建议：** 用即时文字或静态状态替代非必要动效，且不依赖动画回调解锁。
- **复验：** 减弱动态下仍能看到同样信息和完成操作。

### UX-MOTION-03 高频操作被动画拖慢或滥用 transition:all
- **触发：** 每次输入、批量选择或常用快捷操作都要等出场动画；或 `transition: all` 导致布局和状态被意外动画。
- **适用/边界：** 局部反馈约 100–200 ms、面板约 150–300 ms 只是可调起点（见 visual-system.md），**不是**全产品必须小于某阈值。频率、距离和偏好优先。
- **证据：** 高频操作手感与计算样式中的过渡属性。截图不足。
- **严重度：** 一般；明显阻碍连续操作为严重。
- **修复建议：** 显式列出过渡属性；高频操作即时反馈。
- **复验：** 连续输入和批量操作不被动画挡住，无意外过渡。

### UX-PERF-01 布局不稳定或媒体空间未预留
- **触发：** 图片、字体、加载切换造成明显位移，遮住操作或改变点击目标；固定英雄区把内容推出屏幕。
- **适用/边界：** 预留尺寸或纵横比。加载/成功切换不应让按钮跳动。实验室 CLS 与真实用户数据见 verification.md，不能互相替代。
- **证据：** 加载前后或切换状态的布局记录。只有终态截图则部分未验证。
- **严重度：** 导致误点或找不到主行动为严重，否则一般。
- **修复建议：** 预留空间，避免用内容变化把布局顶开。
- **复验：** 关键操作位置在加载前后保持可预期。

### UX-PERF-02 把未实测的性能写成合格
- **触发：** 无测量条件就把页面写成「很快」「不卡」，或用一次实验室结果代替真实用户数据。
- **适用/边界：** 强制审计诚实。Core Web Vitals 的良好目标（LCP ≤ 2.5 s、INP ≤ 200 ms、CLS ≤ 0.1，真实用户第 75 百分位，移动与桌面分开）只在有数据时引用。无 INP 现场数据须如实说明。
- **证据：** 设备、网络、方法和数值；没有就写未验证。
- **严重度：** 把未测写成通过为严重。
- **修复建议：** 删除无依据的性能合格结论，或补测。
- **复验：** 性能结论均带条件与数据，或保持未验证。

### UX-RESP-01 窄屏或中间宽度下必要操作不可用或被遮挡
- **触发：** 必要操作被隐藏、重叠，或被粘性栏、安全区、键盘挡住。
- **适用/边界：** 先保证最窄目标宽度能容纳必要内容。须看手机、中间宽度和桌面，不只看设计断点上的两张图。
- **证据：** 目标宽度截图与实际操作。
- **严重度：** 主行动不可用为严重或阻断，否则一般。
- **修复建议：** 重排或改粘性栏，保证必要操作可及。
- **复验：** 在约定窄宽度下能完成主任务，内容不重叠。

### UX-RESP-02 唯一入口依赖悬停
- **触发：** 关键操作、关键说明或关键数据只在 hover 时出现。
- **适用/边界：** hover 只能增强，不能当唯一入口。触控和键盘须可发现同样能力。
- **证据：** 关闭悬停或在触控/键盘下寻找同一入口。
- **严重度：** 严重。
- **修复建议：** 提供可见或可聚焦的替代入口。
- **复验：** 无悬停也能完成同样任务。

### UX-RESP-03 重排丢失必要数据或整页被撑开
- **触发：** 为了「简洁」直接删除比较所需的列；或一个超宽子元素撑开整页，横向滚动不可发现。
- **适用/边界：** 确需二维结构的数据可在局部滚动并保留表头关联，而不是删数据。列表改卡片前先定必需字段。
- **证据：** 窄屏与桌面的字段是否还在，滚动范围是否可被发现。
- **严重度：** 关键数据丢失为严重；整页误滚动为一般或严重。
- **修复建议：** 保留必要字段或提供可发现的局部滚动，避免整页被撑开。
- **复验：** 必要数据仍可及，意外横向滚动消失。

### UX-RESP-04 禁止用户缩放或文字放大后被裁切
- **触发：** 禁止浏览器缩放，或固定高度在放大、长翻译后裁切文字。
- **适用/边界：** 强制不得禁止用户缩放。不要用禁缩放掩盖输入框字号或排版问题。移动输入字号常从至少 16 CSS px 起步并在目标浏览器验证，此为可调默认，不是禁缩放的替代。WCAG 重排与 200% 放大检查见 verification.md。
- **证据：** 尝试缩放和放大文本。
- **严重度：** 禁止缩放为严重或阻断；放大裁切关键内容为严重。
- **修复建议：** 允许缩放与文本调整，用流式布局代替固定高度。
- **复验：** 缩放和放大后主内容与操作仍可用。

## 11. 无障碍

### UX-A11Y-01 键盘无法完成核心任务或出现意外焦点陷阱
- **触发：** Tab/方向键/Enter/Esc 无法完成主任务，或焦点进入后无法离开（非模态的预期陷阱除外）。
- **适用/边界：** 强制。核心任务须键盘可完成。拖放须有非拖动替代。仅截图未验证。
- **证据：** 完整键盘走查步骤。
- **严重度：** 阻断或严重。
- **修复建议：** 按组件模式补齐键盘行为，并提供拖放替代。
- **复验：** 只靠键盘完成主任务，无非预期陷阱。

### UX-A11Y-02 焦点不可见或被遮挡
- **触发：** 焦点没有可见指示，或被粘性头尾、浮层完全挡住。
- **适用/边界：** 强制。优先 `:focus-visible`。WCAG 要求焦点不被粘性头尾完全遮挡。
- **证据：** 键盘移动到关键控件时的可见性。截图未验证，除非专门拍到焦点态。
- **严重度：** 严重或阻断。
- **修复建议：** 提供不被遮挡的可见焦点。
- **复验：** 全程能看到焦点，滚动后仍不被粘性栏盖住。

### UX-A11Y-03 控件缺少正确名称、角色或状态
- **触发：** 图标按钮没有可访问名称；可见标签与无障碍名称相反；自定义控件缺少名称、角色或状态。
- **适用/边界：** 强制。优先原生语义。不要给所有节点乱加 ARIA。折叠图标按钮在视觉上也宜有可见名称或图文组合，不能只在悬停时出现。
- **证据：** 可访问树或读屏抽查。未测读屏可先根据 DOM/ARIA 标疑点，完整结论可标未验证。
- **严重度：** 关键控件无法识别为严重或阻断。
- **修复建议：** 补与可见文案一致的名称、角色和状态。
- **复验：** 每个交互控件都能被正确指出名称和状态。

### UX-A11Y-04 对话框或浮层的焦点与关闭行为不符合模式
- **触发：** 打开后焦点未进入对话框；背景仍可交互；Esc 无效；关闭后焦点丢失或跑到页顶；把关闭当成已提交。
- **适用/边界：** 参照 WAI-ARIA APG 对话框模式。能做成独立页时不必强行叠层。截图未验证。
- **证据：** 打开、Tab 循环、Esc、关闭后焦点位置，以及关闭与提交的区别。
- **严重度：** 严重或阻断。
- **修复建议：** 使用已验证的对话框实现，并区分取消、关闭与保存。
- **复验：** 焦点进入、圈定在模态内、关闭后回到合理位置，关闭不等于提交。

### UX-A11Y-05 状态变化不能被辅助技术获知
- **触发：** 搜索结果数量、保存成功、上传失败等不移动焦点的状态变化，辅助技术完全不知道；或把每个按键、每帧进度都做成打断性播报。
- **适用/边界：** 见 WCAG 状态消息：不移动焦点的状态也应可被获知。紧急才用打断性播报。客户端路由后标题和焦点策略应可预期。未做读屏则未验证。
- **证据：** 读屏走查或等效状态机制检查。
- **严重度：** 关键失败不可知为严重；过度播报为一般。
- **修复建议：** 用适当状态消息，合并频繁更新，错误还要能再次找到。
- **复验：** 关键状态可被听到或再次定位，且不会被垃圾播报淹没。

### UX-A11Y-06 图像与图标的替代文本不当
- **触发：** 信息性图片没有替代文本；装饰图被重复朗读；复杂图表既无结论也无数据访问方式；视频未播放就无法理解首屏。
- **适用/边界：** 信息图要有适当替代；纯装饰用空替代。首屏关键内容不依赖视频才可理解。
- **证据：** 图片职责与替代文本；关闭媒体后的页面理解。
- **严重度：** 关键信息只在图或视频里为严重，否则一般。
- **修复建议：** 按职责补替代或数据访问，删除无职责且抢注意力的装饰。
- **复验：** 不看图或视频也能理解关键信息，装饰不被重复朗读。

## 12. 待执行的研究检查

以下不是已完成的实测结论，也不是「不检查就判不通过」。未做就记入待验证，不得写成已访谈或已测试。

### UX-RES-01 目标用户与任务假设尚未验证
- **触发：** 方案依赖特定用户动机或使用情境，但没有相应访谈、支持请求或使用数据。
- **适用/边界：** 综合补充。允许基于假设设计，但必须标明是假设。
- **证据：** 研究材料或明确的假设清单。
- **严重度：** 不因未做研究而判界面不通过；若把假设写成事实，按 UX-META-02 处理。
- **修复建议：** 列出待验证假设，必要时安排研究。
- **复验：** 交付把假设与已证实发现分开。

### UX-RES-02 关键任务尚未做可用性观察
- **触发：** 争论用户会不会迷路、会不会误点，但没有走查、可用性任务或行为数据。
- **适用/边界：** 综合补充。启发式走查不能冒充用户测试。
- **证据：** 测试计划或结果；没有则未验证。
- **严重度：** 同上，不自动判界面不通过。
- **修复建议：** 对关键任务设计可观察的成功条件并测试。
- **复验：** 若引用行为结论，须有样本和任务条件。

### UX-RES-03 信息架构尚未用方法验证
- **触发：** 导航分组或命名有争议，且未做卡片分类、树测试或等效验证。
- **适用/边界：** 综合补充。未做不等于结构一定错误。
- **证据：** 研究方法与结果，或标明未验证。
- **严重度：** 不自动判不通过。
- **修复建议：** 在改信息架构前计划验证方法。
- **复验：** 结构结论与验证状态相符。
